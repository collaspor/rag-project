# RAG Resume Evaluation Plan

## 目标

当前 `em / sub_em / f1 / precision / recall` 更偏向“生成文本和标准答案的词面重合度”，适合做基础自动评测，但不适合直接作为简历中的核心成果指标。更适合简历展示的方案，应同时覆盖检索效果、生成效果和系统性能。

## 建议保留的指标

1. 检索层
- `Retrieval Recall@K`：前 K 个召回结果中，是否至少命中一个包含标准答案的 chunk。
- `Retrieval Precision@K`：前 K 个召回结果中，有多少比例包含标准答案。
- 建议重点写 `Recall@3` 和 `Recall@5`。

2. 生成层
- `EM`：适合短答案问答，不适合长段落答案。
- `F1`：可保留，但只能作为辅助指标。
- `ROUGE-L`：比 EM 更适合长文本问答场景。
- 建议增加“答案可用率”人工评测：按“正确 / 部分正确 / 错误”三档标注 100 条样本。

3. 工程层
- 平均响应时延：`检索耗时 + 生成耗时`。
- P95 响应时延。
- 平均输入 token 数：评估 prompt 和上下文压缩效果。

## 适合简历的对比实验

在 AutoDL 上固定同一批测试集，跑 3 组实验：

1. `LLM Only`
- 不走检索，直接回答问题。

2. `RAG Base`
- 使用当前向量检索 + Prompt 生成。

3. `RAG + Rerank`
- 在 `RAG Base` 基础上开启 reranker。

## 测试集设计建议

当前 `test_2.jsonl` 可作为自动回归集，但不建议直接拿来写简历。建议额外人工整理 100 条高质量 QA：

- 40 条事实型问题：如“某制度的申请条件是什么”
- 30 条流程型问题：如“报销流程分几步”
- 20 条比较型问题：如“差旅报销和采购报销的区别”
- 10 条异常型问题：如“未命中知识库时系统如何回复”

标准答案应控制在 1 到 3 句，避免直接复制整段 chunk。

## 简历中可使用的量化表述模板

- 将知识问答评测拆分为检索命中、答案生成和系统性能三层指标，构建自动化评估流程。
- 相比 `LLM Only`，`RAG Base` 在 `Recall@3`、`ROUGE-L` 上显著提升，验证私有知识引入后可有效降低幻觉。
- 通过加入 reranker，对比实验进一步提升召回结果相关性，减少无关片段进入 Prompt。
- 基于 100 条人工标注 QA 集和 1000 条自动回归集形成双层评测体系，兼顾真实性和迭代效率。

## 结合你当前项目的保守写法

在尚未补齐人工标注集前，建议这样写，风险最低：

- 设计并落地 RAG 自动化评测链路，覆盖 EM、F1、Precision、Recall 等生成指标，并支持后续扩展检索命中率与 ROUGE 评测。
- 构建 1000 条知识库自动测试集，用于验证检索增强后回答质量的稳定性与可回归性。
- 基于私有文档检索与引用生成，降低大模型在企业知识问答场景下的幻觉风险，提升答案可追溯性。

3. 跑 `LLM Only / RAG Base / RAG + Rerank` 三组对比。
4. 记录最佳一组结果，提炼为简历数据。
